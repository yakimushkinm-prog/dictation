# Диктовка

Хоткей на маке → говоришь → нажимаешь ещё раз → текст вставляется под курсор в любом
приложении. Распознавание идёт на своём GPU, а не в чужом облаке.

Полный круг — **0.2–0.5 с** на обычную фразу (RTX 5070). Звук не покидает домашнюю сеть и
нигде не сохраняется.

```
[Mac] хоткей → запись → SSH-туннель :9876 → [ПК с GPU] FastAPI → faster-whisper → текст → вставка под курсор
```

## Зачем

Системная диктовка либо облачная, либо посредственная, а хорошие облачные сервисы хотят твой
голос у себя на серверах. Здесь настоящая модель Whisper работает на твоём железе, доступна
только через приватный туннель, и ощущается как встроенная функция ОС: одна клавиша, без окон и
без копипаста.

Ограничение, определившее весь дизайн: **должно быть достаточно быстро, чтобы диктовать посреди
фразы.** Больше секунды — и ты перестаёшь этим пользоваться.

## Состав

| | |
|---|---|
| `mac/client.py` | Приложение в меню-баре: хоткей, запись, отправка, вставка |
| `server/server.py` | FastAPI-сервис с `/health` и `/transcribe` |
| `server/transcriber.py` | Обёртка над faster-whisper — ленивая загрузка, GPU с фолбэком на CPU |
| `mac/launchd/` | launchd-агенты: держат клиент и SSH-туннель живыми |
| `server/dictation.service` | systemd user-юнит для сервера |

## Установка

### 1. Сервер (машина с GPU)

Linux или WSL2 с картой NVIDIA. Скопируй `server/` в `~/dictation/server`:

```bash
cd ~/dictation/server
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

Поставь как user-сервис, чтобы жил без активной сессии:

```bash
sudo loginctl enable-linger "$USER"
mkdir -p ~/.config/systemd/user
cp dictation.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now dictation
curl -s localhost:9876/health     # {"status":"ok","device":"cuda"}
```

Сервис слушает только `127.0.0.1`. Наружу ничего не торчит — доставка это задача туннеля.

Переменные окружения: `DICT_MODEL` (по умолчанию `medium`), `DICT_DEVICE` (`auto`),
`DICT_LANG` (по умолчанию `ru`; пустое значение — автоопределение).

### 2. Туннель (на маке)

```bash
cp mac/launchd/com.leshwas.dictation-tunnel.plist.example \
   ~/Library/LaunchAgents/com.leshwas.dictation-tunnel.plist
```

В копии подставь `__USER__`, `__HOST__`, `__PORT__` и `__SSH_KEY__`, затем:

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.leshwas.dictation-tunnel.plist
curl -s localhost:9876/health     # тот же ответ, что и на ПК — туннель поднят
```

### 3. Клиент (на маке)

```bash
cd mac
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp config.example.toml config.toml
python client.py
```

В меню-баре появится 🎙. Нажми хоткей (по умолчанию бэктик `` ` ``), говори, нажми ещё раз.
Пункт меню **Тест: записать 4 сек** проверяет микрофон без хоткея.

macOS попросит доступ к **микрофону**, **Универсальному доступу** и **Мониторингу ввода**.
Нужны все три: первый — чтобы записать, остальные — чтобы отправить нажатие Cmd+V.

Автозапуск при входе — так же, через `com.leshwas.dictation.plist.example`. Полноценный бандл
с собственной идентичностью (тогда системные запросы доступа ведут себя корректно):

```bash
python setup.py py2app -A
```

## Настройки

`mac/config.toml`:

| Ключ | По умолчанию | |
|---|---|---|
| `server_url` | `http://127.0.0.1:9876` | локальный конец туннеля |
| `hotkey` | `` ` `` | формат pynput; одиночная клавиша вроде `` ` `` продолжает печатать свой символ — если мешает, ставь комбинацию, например `<ctrl>+<alt>+d` |
| `sound` | `true` | щелчок на старт и стоп |
| `restore_clipboard` | `false` | вернуть прежний буфер обмена после вставки |

## Решения по реализации

То, что получилось не с первой попытки — и в чём, собственно, вся сложность:

**Запись через AVFoundation, а не PortAudio.** Очевидный выбор `sounddevice` на современной
macOS пишет тишину, если процесс не запросил доступ к микрофону как положено, и запросить его
оттуда нельзя. `AVAudioRecorder` спрашивает систему так, как система ожидает: пользователь видит
диалог, а в файле оказывается звук. Клиент проверяет размер записанного файла и говорит
«микрофон не записал звук (доступ?)» вместо отправки пустого файла и загадочного пустого ответа.

**Вставка через Quartz `CGEvent`, а не эмуляцию pynput.** Эмулированный Cmd+V игнорирует изрядное
число приложений. Настоящее событие клавиатуры в HID event tap работает везде, включая
Electron-приложения и терминалы.

**Модель грузится на старте, а не на первом запросе.** Без прогрева первая за день диктовка
занимает несколько секунд, пока веса едут на карту — ровно в тот момент, когда новый пользователь
решает, что инструмент тормозит. Хук `lifespan` в FastAPI грузит модель до того, как сервис
сообщит о готовности.

**Отказ GPU деградирует, а не ломает.** Транскрайбер пробует CUDA, уходит на CPU, если карта
недоступна, и — поскольку ctranslate2 умеет успешно создать CUDA-модель и упасть только на
инференсе — один раз пересобирается на CPU, если инференс бросил исключение. Любая ошибка
распознавания возвращает пустую строку, поэтому клиент показывает «ничего не распознал», а не
ошибку.

**cuBLAS и cuDNN подгружаются вручную под WSL.** ctranslate2 ищет их через `dlopen`, а в WSL их
нет в системных путях — зато они есть внутри pip-пакетов `nvidia-*`. Сервер загружает эти `.so` с
`RTLD_GLOBAL` на импорте, что избавляет от правки `LD_LIBRARY_PATH` в юните. Best-effort: нет
пакетов — молча работаем на CPU.

**`compute_type` = `int8_float16`.** Около 1.5 ГБ VRAM, точность почти как у `float16` — выбрано
так, чтобы модель умещалась на карте 12 ГБ рядом с языковой моделью.

## Безопасность

Звук идёт по SSH-туннелю внутри приватной сети. Сервер слушает только loopback, временный WAV
удаляется после распознавания, больше на диск ничего не пишется ни с одной стороны.
Аутентификации в самом сервисе нет — чтобы вообще достучаться до порта, нужен твой SSH-ключ, и
это осознанная модель угроз. Не биндить на `0.0.0.0`.
